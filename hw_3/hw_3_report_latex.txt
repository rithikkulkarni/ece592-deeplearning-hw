\section{Task 2: Node property prediction (Q5)}

## Question 5: What are your best_model validation and test accuracies? (20 points)

\subsubsection*{Implementation}
I implemented the GCN using the same architecture given in the figure shown in the assignment instructions slides. The model has 3 layers with a hidden dimension of 256. The first layer maps the 128 input features to the 256, then the second layer maps 256 to 256, and the third one maps the 256 to the 40 output classes. Each of the first two convolutions (\texttt{GCNConv}) is followed up by BatchNorm, ReLU, and dropout ($p=0.5$). The final convolution is only followed up by \texttt{LogSoftmax}. over the class dimension. I made sure that dropout is applied with \texttt{training=self.training} so that it is always disabled during evaluation. The training is full-batch, so each step runs the entire graph through the model, but the loss is only computed on the training nodes.

\subsubsection*{Baseline results}
I first trained the plain architecture with the default hyperparameters (3 layers, hidden dimension 256, dropout 0.5, learning rate 0.01, 100 epochs). The best model was selected by validation accuracy, which peaked at epoch 96.

\subsubsection*{Observations}
\begin{itemize}
    \item The model didn't converge. The training loss continuously decreased every epoch all the way through epoch 100 (ended at 0.9155), and validation accuracy was also still slowly rising. Training finished before the model finished learning.
    \item The training accuracy was only about 1.6\% higher than the validation accuracy, and both were still increasing. This signals that the model wasn't overfitting.
    \item Test accuracy is consistently lower than the validation accuracy. The model is trained on older papers, validated on 2018 papers, and tested on 2019 papers. The test set is the furthest forward in time from the training data, which helps this make sense.
\end{itemize}

\subsubsection*{Enhancement: Residual Connections}
This next experiment adds residual (skip) connections to the hidden layers. Whenever a layer's input and output have the same dimension, the layer's input is added back to its output. Residual connections allow each layer to learn a correction to its input rather than creating a fully new representation. This helps preserve node-specific information that gets diluted by repeated averaging. I kept all previous hyperparameters the same as the baseline.

Only the middle layer currently uses a residual connection. For this run, I fixed the random seed to be 6666 so that the weight initialization and dropout masks would be reproducible.

\subsubsection*{Residual Observations}
\begin{itemize}
    \item The residual model scored lower, but most of this difference seems to be noise than something real. Accuracies across the board dropped slightly.
    \item The two runs started from different random initializations, so this is a comparison run-to-run as well as a slight architectural change.
    \item It's likely that the residual connections had very little improvement to give. They are mainly to counter over-smoothing due to averaging, but that effect is already quite weak in a 3-layer network.
    \item This model is also undertrained, reaching its best epoch at 100. This signals that an increase in epoch count is in order.
\end{itemize}

I removed the residual connections and returned to the plain default architecture suggested in the instructions. I simply increased the number of training epochs from 100 to 500, and will see if that helps (keeping the fixed seed of 6666 from the residual experiment).

\subsubsection*{500 Epoch Observations}
\begin{itemize}
    \item Longer training improved the validation accuracy further, but not the test accuracy. This suggests that there is some generalization gap rather than classic overfitting.
    \item Training accuracy continued to rise faster than the validation accuracy, created a substantial gap. This is not classic overfitting, however, because the validation accuracy never actually started decreasing again. This just shows that there's large diminishing returns to extra training, and that the extra training just went into fitting the specific training nodes rather than improving generalization.
    \item The original baseline and longer training reached similar best test accuracies, so training longer does not seem to be the sole solution.
\end{itemize}

\subsubsection*{Enhancement: Lower Learning Rate}
The test accuracy from the 500-epoch run seemed to fluctuate a lot between rpochs, so the epoch with best validation accuracy sort of landed on a ``random'' point. To make the training more stable, I halved the learning rate (0.01 to 0.005), keeping the 500 epochs and the rest of the architecture.

\begin{lstlisting}
Saving Model Predictions
Best model: Train: 78.93%, Valid: 73.18% Test: 71.83%
\end{lstlisting}
\\
This run gave the highest peak validation accuracy (73.18\% at epoch 391) as well as the highest test accuracy for the best model (71.83\%) out of any experiment so far. The 10 epochs with the highest validation accuracy all had test accuracies between 71.53\% and 72.21\%, which when compared to the 71.05\%--71.94\% in the earlier 500-epoch run, is definitely better. This signals that the lower learning rate increased our performance slightly.

Additionally, we achieved best test accuracies of $>$72\%, but these were from models with lower validation accuracies. We cannot reliably pick a model based on its test accuracy since that is unknown when we deploy something, so we can only assume the best validation accuracy will result in the best test accuracy. This means that we must choose the best validation accuracy model, which gave us a best test accuracy of 71.83\%.

\subsubsection*{Enhancement: Higher Dropout}
Every run so far has showed the same pattern of training accuracy climbing higher and higher while the validation and test accuracies barely moved, which meant the extra training was mostly just spent fitting to the training nodes. To fight this, I increased dropout from 0.5 to 0.6 while keeping everything the same. The goal here was not to see us suddenly beat the 72\% baseline, but to hopefully see a decrease in the gap between training and validation accuracies.

\begin{lstlisting}
Saving Model Predictions
Best model: Train: 77.12%, Valid: 73.06% Test: 71.66%
\end{lstlisting}
\\
Turns out that the higher dropout worked as intended. The training-validation gap decreased from the previous 5.75\% down to 4.06\%, while the validation accuracy and test accuracy stayed roughly the same. On its own, this doesn't improve our performance outright, but it did reduce the model's tendency to overfit to/memorize the training nodes. This now leaves room for us to increase the model's capacity without the risk of overfitting, which is what gave me the idea for my next experiment.

\subsubsection*{Enhancement: Wider Hidden Layers}
Keeping dropout at 0.6, I increased the hidden dimension from 256 to 512, so the model layers became $128 \rightarrow 512 \rightarrow 512 \rightarrow 40$. This means every node has a larger representation (around 3 times as many total parameters), which lets the model encode finer details regarding the 40 classes. Without having increased dropout, this wider model would likely overfit.

\begin{lstlisting}
Saving Model Predictions
Best model: Train: 80.36%, Valid: 73.41% Test: 72.19%
\end{lstlisting}
\\
This run achieved our target baseline of $>$72\% accuracy for our best model (picked by validation accuracy). Our training-validation gap is back up to 6.95\%, but this is expected since the wider model has more capacity to directly fit training nodes, but our overall accuracy improved.

\subsubsection*{Baseline Observations}
\begin{itemize}
    \item The validation ROC-AUC is noisy between epochs. One example is that it reached 79.40\% at epoch 15, then dropped all the way to 72.17\% at epoch 21, and then rose back up to 79.90\% at epoch 26. The class imbalance could be playing a major role in this noise, and this means the epoch that we select as the best model could potentially have been based on random chance/luck.
    \item There is a large gap between validation and test ROC-AUC (roughly 4\%). This gap is much larger than the gap we saw in the second assignment task.
    \item At the end of this training run, the model was still improving. The training ROC-AUC was steadily rising and still increasing at epoch 30, where it reached 84.64\%.
\end{itemize}

This first test is above the sanity check of 74\% but still well below the target baseline of 77\%. The next step will be trying the other two global pooling methods (sum and max) to see if they give a better test ROC-AUC.

\subsubsection*{Enhancement: Sum Pooling}
Mean pooling averages the atom embeddings, so two molecules with the same proportions of atom types look similar even if one is much larger or contains more copies of a chemical group. Sum pooling instead adds up the atom embeddings, so the graph embedding keeps information about counts and molecule size. I replaced \texttt{global\_mean\_pool} with \texttt{global\_add\_pool} and kept everything else the same, including the seed.

\subsubsection*{Sum Pooling Observations}
\begin{itemize}
    \item Sum pooling ended up very close to mean pooling. Validation ROC-AUC was slightly higher (80.29\% vs.\ 79.90\%) and test ROC-AUC was slightly lower (75.59\% vs.\ 75.86\%). Given how noisy validation ROC-AUC is between epochs, these differences are too small to say that either pooling method is better.
    \item Training started off noticeably worse and was less stable. After the first epoch, training ROC-AUC was 62.88\% with sum pooling compared to 72.07\% with mean pooling, and validation ROC-AUC swung even more widely (e.g.\ 74.01\% at epoch 8, 64.51\% at epoch 11, and 66.25\% at epoch 21). A likely reason is that summed embeddings grow with the number of atoms, so the scale of the inputs to the final linear layer varies a lot between small and large molecules, which makes the model harder to train early on.
    \item The validation--test gap was slightly larger (4.70\% vs.\ 4.04\%), so the extra size and count information did not help the model generalize to the structurally different molecules in the test set.
\end{itemize}

Sum pooling did not improve the test ROC-AUC, so I next tried max pooling.
